## Applicability and numerical behavior

- Row-limit results use pruned INT8 checkpoints and comfy_kitchen. All tested 4090 shapes improved; the production default change remains scoped to RTX 5090 H3. H200 default JIT does not use the kitchen row limit.
- FP32 modulation applies to eligible FP32 AdaLN tensors. Pruned H3 with H200 default JIT also improved by 3.44%; the full BF16 H3 checkpoint did not enter the new kernels. H3 outputs were bit-identical in the tested model and workflow comparisons.
- Qwen INT8 packing applies to serialized kitchen weights, TP=1, resident CUDA weights, with storage guards and fallback. H200 default JIT packed 0/32 layers and is unaffected. INT8 differs numerically from the old separate SGLD sequence; checks match the installed native kitchen fused SwiGLU reference sequence exactly. This alone does not establish whole-pipeline equality with stock ComfyUI.
- BF16 packing remains experimental: gains are small or negative. On RTX, actual 55-token prefix merged GEMM outputs differ from separate GEMMs; the activation remains bit-identical given identical projections. Cached-prefix same-input checks cannot establish end-to-end bit identity. Do not enable BF16 by default based on these results.

## Method and evidence

- One pinned production commit; same Qwen BF16 and INT8 files verified by actual SHA256 on all three hosts. Each variant uses a fresh private ComfyUI server/base directory. No host PSS scanning, profiler during macro timing, or GPU-clock changes.
- Same-input diagnostic: initialize Qwen prefix cache, prime both variants, ABBAABBA, four samples per arm, synchronized timings and repeated-output/input-ownership checks. 35 comparisons passed validity checks.
- Normal workflow: H3 4 steps × 3 seeds; Qwen INT8 8 steps × 3; BF16 also 20 steps × 3. The 20-step BF16 batch uses a warmup-only, self-removing observer; reported memory should use the unobserved 8-step batch. Separate prefix probes are numerical diagnostics only.
- H200 original Ref2VA had one unexplained 107 GiB occupancy/slow sample. Raw data is retained; the table uses a fresh full three-variant rerun with GPU-process auditing. Do not describe the cause as confirmed external interference.
- ComfyUI commit `b0b743566f65daafc423b4fea8a2fbda94b3384a`, kitchen 0.2.37 on all hosts. RTX used torch 2.14.1 / Triton 3.8.0; H200 used torch 2.13.0 / Triton 3.7.1. Per-host paired impacts are valid; hardware-only attribution is not isolated.

The evidence entry point is `cross-gpu-pr-validation-20261014/README.md` in the benchmark results area. It includes the Chinese detailed report, paired samples, finite-value/latent/image checks, runtime script snapshots, per-file manifests, environment identity and process audits. ## Reproduction entry points

`cross_gpu.py` supports `--stage diagnostic|formal`, `--cases`, `--steps`, `--repetitions`, `--variants`, and a separate `--batch-label`. Set `CROSS_GPU_SOURCE` to the isolated pinned checkout, and source the host benchmark environment first. It requires an idle selected GPU and uses an experiment lock. Follow-up observer and microbenchmark scripts are preserved with their runtime hashes in the evidence bundle; they are not required for the uninstrumented normal workflow.

Suggested PR split: H3 row limit, H3 FP32 modulation, Qwen INT8 MLP. Keep BF16 packing opt-in and separate. No PR has been created by this validation.
